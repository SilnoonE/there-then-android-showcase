# 개발·업로드 과정 요약

앱의 기능을 웹으로 옮기고 파일 공유를 검증한 과정을 정리했습니다. 재현 가능한 전체 배포 매뉴얼이 아닌 개발 흐름의 개요입니다.

## 1. 웹에서 이어갈 사용 흐름 정리

방문 기록·동행·지도에 약속 뽑기와 타임캡슐을 연결했습니다. 파일 공유부터 완성한다는 범위를 정하고, 온라인 공개 링크와 자동 동기화는 별도 후속 단계로 남겼습니다.

## 2. 브라우저 기본 기능 구현

기록과 사진을 브라우저에 보관하고, 저장 성공 후 화면을 갱신하도록 구성했습니다. 앱과 같은 색감으로 PC와 모바일 메뉴를 나눴습니다. 편집 화면을 전환한 뒤에도 사진을 추가하고 저장하는 흐름을 확인했습니다.

## 3. 가져오기·백업·부분 공유 분리

파일을 읽자마자 기존 기록을 덮어쓰지 않고 내용과 선택지를 먼저 보여 줍니다. 전체 보관용 백업과 다른 사람에게 보내는 부분 공유를 구분하고, 이름·메모·위치의 포함 여부를 선택하게 했습니다.

## 4. 자동 검사와 실제 화면 확인

날짜·예산·파일 왕복·공유 범위 검사를 실행했습니다. 브라우저에서는 사진을 넣어 저장하고 새로고침한 뒤 보존되는지, 공유 ZIP을 내려받아 다시 추가할 수 있는지 확인했습니다. HTML 공유 파일에 사진이 들어가고 기본 설정에서 개인 메모가 빠지는지도 확인했습니다.

## 5. 배포할 자료 정리

새 웹 소스와 필요한 정적 자산·라이브러리 라이선스를 모았습니다. Android 원본 프로젝트, 서명 정보, 실제 개인 기록과 사진이 배포 소스에 섞이지 않았는지 점검했습니다.

## 6. 비공개 미리보기 업로드와 배포

검증한 웹 작업본을 전용 비공개 호스팅 저장소에 저장하고, 같은 소스로 만든 정적 배포 파일을 업로드했습니다. 배포 도구의 성공 결과를 확인하고 소유자 로그인으로 접근하는 미리보기 주소를 준비했습니다.

호스팅 로그인 이후 화면의 실사용 검증은 아직 하지 않았습니다. 기능 검사는 동일한 소스의 로컬 미리보기에서 수행했습니다. 일반 공개와 사용자 도메인 연결은 후속 단계입니다.

## 이 공개 저장소에 올린 자료

기능 소개, 개략적인 구조도, 과정과 검증 범위, 일반화한 짧은 예제만 올립니다. 전체 웹 소스와 실제 배포 명령, 호스팅 설정·식별자·접근 정보, 원본 테스트 파일·백업은 포함하지 않습니다. 과거 개발 단계를 실제 Git 커밋 이력처럼 재구성하지 않았습니다.
