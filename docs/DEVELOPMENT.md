# 개발 과정과 판단

## 출발점

방문한 맛집 목록을 만드는 데서 한 단계 더 나아가, 누구와 갔는지를 함께 저장하자는 요구에서 시작했습니다. 연인·친구·가족으로 기록을 묶을 수 있도록 동행 프로필과 사람별 앨범을 핵심 흐름에 넣었습니다.

## 초기 버전에서 선택한 것

| 요구 | 구현 선택 | 이유와 한계 |
|---|---|---|
| 곧바로 기록 시작 | 로컬 프로필, 서버 가입 없음 | 시작 부담이 작지만 여러 기기 동기화는 제공하지 않음 |
| 지도에 장소 저장 | Leaflet·OSM, 기기 Geocoder | 별도 개발자 키 없이 초기 구현 가능; 검색 품질·타일 운영 검토 필요 |
| 누구와 갔는지 보기 | 기록과 동행을 식별자로 연결 | 이름 변경과 여러 동행을 다룰 수 있음 |
| 예쁜 기록 공유 | 이미지 카드와 공유 옵션 | 온라인 공개 피드 없이 원하는 기록만 전달 |
| 사진까지 옮기기 | 사진 포함 백업 | 문서만 저장해서 사진이 사라지는 경험 방지 |

## 시각 구성

크림색 종이와 자주색 잉크, 귤색 포인트를 사용하고 사진과 짧은 문장을 중심에 뒀습니다. 기록이 없는 상태에서도 사용 방법을 알 수 있도록 구성하고, 예시 앨범은 사용자가 직접 불러오도록 분리했습니다.

## 구현에서 중요하게 본 점

- 사람 이름과 연결 식별자의 역할을 나눕니다.
- 좌표는 위도·경도를 함께 다루고 유한한 값과 범위를 확인합니다.
- 사진을 선택한 뒤 앱 내부 저장소로 가져옵니다.
- 저장 실패와 읽기 실패를 정상 상태처럼 처리하지 않습니다.
- 공유 이미지에 넣을 이름과 메모를 사용자가 선택하게 합니다.

## 다음 검토

실제 기기의 큰 글꼴·적은 메모리 환경, 사진이 많은 백업, 지도 검색 실패, 장기 사용에서의 데이터 관리와 화면 코드 분리가 후속 검토 대상입니다. 지도 제공자 선택은 이용량과 정책을 확인한 뒤 결정해야 합니다.

이 문서는 현재 코드와 개발 대화의 요약입니다. 개발 과정의 모든 단계를 과거 Git 커밋으로 재현하지 않았으며, 공개 저장소는 이 스냅샷부터 시작합니다.
